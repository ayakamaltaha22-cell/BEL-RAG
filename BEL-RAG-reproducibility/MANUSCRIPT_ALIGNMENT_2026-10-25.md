## Notable manuscript-internal configuration discrepancies

Section 9.1 gives a **joint reference** of `tau=0.90`, `lambda=0.05`, `alpha=0.50`, clipping `[0.01,0.99]`, eight passages and three rounds. Section 9.8.2 gives separate one-factor sweep rows whose apparent best values include `tau=0.80`, `lambda=0.10`, and a clipping row of `[0.05,0.95]`. These are not interchangeable joint reference settings; the code must not silently substitute them. `configs/reference.yaml` retains the joint reference, while `configs/manuscript_reported_sweeps.json` transcribes the separate published sweep summaries. These values are manuscript transcriptions, **not generated by this package**.

The manuscript's Table 1 citation for Zeng et al. is `[12]` while its related-work text and bibliography use `[26]`. This is a manuscript citation discrepancy, not a code result.

## Execution and reproducibility

Run `python -m pytest -q`. The new tests check formulas independently of any original benchmark data. Run `python -m src.audit_benchmark --out results/audit_stress --seed 13 --per-kind 50 --tau 0.90` to reproduce the *controlled generated-evidence audit* (wall-clock times may differ by machine). The historical four-dataset QA benchmark, matched PolicyRAG Table 7, and native matched-calibration protocol cannot be independently rerun from this archive.

The existing `belrag/core.py` demo uses `entropy(p_before)-entropy(p_after)-lambda*cost`, which is **not** the three-outcome expected utility of Section 6.3.2. The new `acquisition_utility` function requires explicitly supplied outcome probabilities and hypothetical next posteriors and refuses incomplete distributions. Until a trained outcome predictor and fitted conditional model are supplied, it is a verified mathematical utility function, not a fully connected historical controller.
